# AVD Operation Checklist

## 1. 目的

この文書では、AVD運用作業で共通して確認すべきチェック項目を整理する。

AVD運用では、作業そのものよりも、作業前の対象確認、作業中の判断、作業後の残存確認が重要になる。確認観点が作業者ごとに異なると、利用者影響、削除漏れ、証跡不足が発生しやすい。

そのため、作業前、作業中、作業後に分けて、最低限確認する項目を標準化する。

## 2. チェックリストの使い方

このチェックリストは、個別手順書の代替ではない。

作業前後で確認すべき観点を揃えるための補助として使う。

| 区分 | 用途 |
|---|---|
| 作業前 | 対象、前提、影響範囲、承認状態を確認する |
| 作業中 | 実行結果、スキップ理由、想定外事象を確認する |
| 作業後 | 状態、残存リソース、Evidence、回答内容を確認する |

## 7. 判断が必要な場合

以下の場合は、作業者判断で進めない。

| ケース | 対応 |
|---|---|
| Active sessionがある | 依頼元または運用責任者へ確認する |
| 既存AssignedUserを上書きする必要がある | 承認を確認する |
| Disk削除可否が不明 | 削除しない。確認へ回す |
| BackupやLockがある | 解除可否を確認する |
| IDまたは権限側が未確認 | 確認不可範囲として依頼元へ返す |
| 影響範囲が不明 | 作業を保留する |

## 8. Evidenceとして残すもの

| Evidence | 内容 |
|---|---|
| 事前確認結果 | 作業対象、状態、利用者影響 |
| DryRun結果 | 実行予定操作、スキップ対象、スキップ理由 |
| 実行結果 | 成功、失敗、スキップ |
| 作業後確認 | 残存リソース、割当結果、状態確認 |
| 顧客回答 | 調査結果、追加確認依頼、完了報告 |

## 9. まとめ

AVD運用では、チェックリストを作業者の記憶代わりに使う。

確認項目を標準化することで、作業者依存を減らし、利用者影響、削除漏れ、確認漏れ、証跡不足を抑える。
