# Customer Response Template

## 1. 目的

この文書では、AVD運用における顧客または依頼元への回答テンプレートを整理します。

障害対応や作業完了報告では、確認した事実、判断、未確認範囲、次に必要な確認を分けて伝える必要があります。

## 2. 基本方針

| 方針 | 内容 |
|---|---|
| 事実と判断を分ける | 確認結果と推定を混ぜない |
| 確認範囲を明記する | どこまで確認したかを示す |
| 未確認範囲を隠さない | 権限外、範囲外、不足情報を明確にする |
| 次アクションを示す | 顧客側確認、追加情報、運用側対応を分ける |
| 過剰に断定しない | 確認できていない内容を断定しない |

## 3. 接続不可時の一次回答

```text
お問い合わせいただいた件について、対象AVD環境の状態を確認しております。

現時点では、以下の観点で確認を進めています。

・対象HostPoolおよびSessionHostの登録状態
・対象SessionHostの使用可否
・Active sessionの有無
・AssignedUserおよび利用権限の状態
・対象VMの起動状態
・AVD管理面で確認できるエラーの有無

確認結果がまとまり次第、改めてご連絡いたします。
```

## 4. AVD基盤側に明確な異常がない場合

```text
対象HostPoolおよびSessionHostの状態を確認したところ、AVD管理面では対象SessionHostは使用可能な状態であり、基盤側で明確な異常は確認されませんでした。

また、対象SessionHostについては、現時点でHostPool上に登録されており、新規接続を受け付けない設定にもなっていないことを確認しております。

一方で、認証状態、条件付きアクセス、ユーザーリスク、AD / Entra ID側の状態については、当方の確認範囲外となります。

恐れ入りますが、対象ユーザーのID状態および認証条件について、貴社側にてご確認をお願いいたします。
```

## 5. Active sessionがあるため作業を保留する場合

```text
対象SessionHostを確認したところ、現在Active sessionが存在していることを確認しました。

利用中ユーザーへの影響を避けるため、現時点では削除または停止作業は実施しておりません。

作業を継続する場合は、対象ユーザーの利用終了後、または切断可能であることをご確認のうえ、再度ご依頼ください。
```

## 6. AssignedUser割当完了報告

```text
ご依頼いただいたPersonal DesktopのAssignedUser割当について、対象SessionHostへの割当を実施しました。

作業後、対象SessionHostに想定ユーザーが割り当てられていることを確認しております。

なお、Desktop Application Groupの利用権限については、環境側の設定状況に依存するため、接続確認時に利用不可となる場合は、DAG側の権限状態もあわせてご確認ください。
```

## 7. 前提不足により対応保留する場合

```text
ご依頼内容を確認しましたが、現時点では作業対象または実施条件を特定するための情報が不足しております。

作業前提を確認するため、以下についてご教示ください。

・対象HostPool名
・対象SessionHost名
・対象ユーザー
・実施希望日時
・利用者影響の許容可否
・作業後に期待する状態

上記確認後、対応可否および作業内容を確認いたします。
```

## 8. 削除作業完了報告

```text
ご依頼いただいた対象SessionHostの削除作業について、作業を実施しました。

作業前にActive sessionが存在しないことを確認し、対象SessionHostおよび関連Azureリソースの状態を確認したうえで対応しております。

作業後、対象SessionHostがHostPool上に残っていないことを確認しております。

なお、関連リソースの削除範囲については、事前に確認した対象に基づいて実施しています。
```

## 9. 確認不可範囲を伝える場合

```text
当方で確認可能な範囲については確認を実施しましたが、以下については当方の権限または運用範囲外のため確認できませんでした。

・対象ユーザーの認証状態
・条件付きアクセスの適用状況
・ユーザーリスクまたはサインインリスク
・端末側の資格情報キャッシュ
・接続元ネットワークの制御状況

上記については、貴社側または該当管理担当にてご確認をお願いいたします。
```

## 10. まとめ

顧客回答では、確認した事実、判断、未確認範囲、依頼事項を分けて記載します。

特に接続不可や削除作業では、基盤側に異常がないことだけではなく、どの範囲を確認し、次にどこを確認すべきかを明確にします。
